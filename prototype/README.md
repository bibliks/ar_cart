# WebAR-СберКот — localhost-прототип

Отдельный локальный прототип по ТЗ. Исходная страница в корне репозитория и GitHub Pages не изменяются.

## Что реализовано

- MindAR image tracking по существующим `marker.png` и `card.mind`;
- камера остаётся фоном AR-сцены, 3D-персонаж стоит перпендикулярно плоскости маркера;
- две версии мок-профиля: без приложения и с приложением;
- состояния `SCAN → LOADING → APPEAR → GREETING → EPISODE → CLOSING → POSTCARD`;
- непрерывный голосовой диалог: после запуска микрофон сам выделяет реплику по короткой паузе, без удержания кнопки;
- мобильное аудио: запуск разблокирует звук жестом пользователя, iOS пишет цельный MP4, а ответы на телефоне воспроизводятся через серверный TTS с резервным системным голосом;
- кнопки-ответы показываются только как резерв без API/микрофона или для редкого ограниченного выбора;
- персонаж двигает головой, корпусом, руками и ногами, пока отвечает;
- непрерывный диалог без автостопа по времени или количеству реплик;
- мягкий переход к продолжению в приложении по естественному итогу темы, без обязательной фразы прощания;
- контекст последних 24 сообщений текущей сессии передаётся модели при каждой реплике;
- бездействие и потеря маркера не закрывают разговор: интерфейс ждёт продолжения;
- повторное сканирование в тот же день с короткой пасхалкой;
- 2D fallback с камерой для WebGL/MindAR-ошибок;
- серверный OpenAI proxy с модерацией входа/выхода, строгой JSON-схемой, одной повторной попыткой и локальным fallback;
- в `localStorage` сохраняются только дата и число сканирований отдельно для каждой версии;
- тестовая аналитика хранится только в памяти вкладки: `window.__sberkotAnalytics`.

## Запуск

Требуется Node.js 20 или новее. Устанавливать зависимости не нужно.

```bash
cd "/Users/biblik/Documents/AR_карта/prototype"
npm start
```

Откройте <http://127.0.0.1:4175/>. Сервер слушает только локальный интерфейс `127.0.0.1`.

Статическая сборка для GitHub Pages создаётся без дополнительных зависимостей:

```bash
npm run build:pages
```

Команда обновляет каталог `../docs`. По умолчанию Pages-сборка обращается к `https://bibliks-sberkot-ar-api.onrender.com`; адрес можно заменить через переменную `PAGES_API_BASE` во время сборки.

Render разворачивает `prototype/server.mjs` по конфигурации [`../render.yaml`](../render.yaml). Ключ задаётся только как секрет `OPENAI_API_KEY` в Render и никогда не попадает в HTML/JS. Публичный backend принимает браузерные запросы только с `https://bibliks.github.io`, ограничивает частоту запросов и не разрешает менять ключ через интерфейс.

Прямые адреса:

- <http://127.0.0.1:4175/without-app/> — профиль без приложения;
- <http://127.0.0.1:4175/with-app/> — активный профиль с приложением;
- <http://127.0.0.1:4175/assets/marker.png> — маркер для второго экрана или печати.

## Проверка веток

| Сценарий | Адрес или действие |
| --- | --- |
| A — без приложения | `/without-app/` |
| B — активный | `/with-app/` |
| C — давно не заходил | `/with-app/?activity=dormant` |
| D — повтор сегодня | пройти второй раз или добавить `?repeat=1` |
| E — backend timeout | добавить `?backend=timeout` |
| F — 2D fallback | добавить `?fallback=1` |

Для проверки интерфейса без системного запроса камеры используйте `?fallback=1&camera=off`.

Кнопка **«Сбросить тест»** удаляет локальный счётчик текущей версии и возвращает базовую ветку.

## OpenAI — опционально

Без ключа кнопки и весь сценарий работают локально. Постоянное прослушивание отключено, а ответы берутся из безопасного сценария. Форма временного ключа доступна только на localhost; в GitHub Pages она скрыта, потому что публичная версия использует секрет Render.

Быстрое подключение без записи ключа на диск:

1. Отзовите ключ, который был опубликован в чате, и создайте новый.
2. Откройте <http://127.0.0.1:4175/> или блок **«Подключить голосовой диалог»** на экране запуска AR.
3. Вставьте новый ключ и нажмите **«Подключить»**.

Страница передаст ключ только локальному серверу `127.0.0.1`; сервер проверит его через OpenAI и сохранит лишь в памяти процесса. После перезапуска Node ключ исчезнет.

Для постоянной локальной конфигурации:

1. Отзовите ключ, который был опубликован в чате, и создайте новый.
2. Скопируйте `.env.example` в `.env`.
3. Добавьте новый ключ только в локальный `.env`:

```dotenv
OPENAI_API_KEY=новый_ключ
```

4. Перезапустите `npm start`.

`.env` исключён из Git. Сервер не пишет ключ, тексты ребёнка или транскрипции в журналы. В OpenAI API передаются только выбранная кнопка или короткая голосовая реплика и обезличенный мок-профиль.

Диалог использует Responses API со Structured Outputs. Распознавание речи использует отдельный endpoint транскрипции. На мобильных устройствах озвучивание выполняет серверный OpenAI TTS, а системный голос браузера остаётся fallback; на desktop используется системный голос.

## Камера и iPhone

`localhost` и `127.0.0.1` считаются безопасным контекстом только на том же устройстве. Поэтому этот этап удобно проверять на Mac с веб-камерой.

iPhone не сможет открыть адрес `127.0.0.1` вашего Mac. Доступ по локальному IP вида `http://192.168…` также обычно не даст камеру из-за отсутствия HTTPS. Для следующего этапа понадобится локальный HTTPS-сертификат или временный HTTPS-туннель; это намеренно не включено в текущий localhost-этап.

## Ограничения прототипа

- `character.glb` — текущий технический placeholder, а не финальная лицензированная модель СберКота;
- CTA показывает подтверждение, но не открывает магазин или приложение: продуктовые deep link и store URL ещё не предоставлены;
- мок-профиль выбирается URL-маршрутом, реального банковского backend нет;
- A-Frame и MindAR загружаются с CDN, поэтому при первом запуске нужен интернет;
- перед продуктовым запуском детского сценария нужны отдельные юридическая, privacy- и security-проверки, согласованный режим хранения API-данных и продуктовая модерация.
